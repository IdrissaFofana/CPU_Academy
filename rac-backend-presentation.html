Decision backend

RAC autonome (non lie aux formations)

Objectif: permettre au super admin de creer des metiers RAC avec des documents requis, puis laisser les utilisateurs postuler sur le site principal avec validation stricte des pieces cote serveur.

Contexte actuel

  • Le RAC actuel est centre sur formationId et le dossier candidat.
  • La page RAC frontend affiche des metiers/documents statiques.
  • Il manque une checklist dynamique par metier et sa validation backend.

Decision cible

  • Le RAC devient un domaine autonome: pas de lien obligatoire a Formation.
  • Le dossier RAC reference un racMetierId.
  • Les documents obligatoires sont definis par metier (admin).

Evolution API demandee (notification de changement)

A modifier
Remplacer l'usage de formationId dans le flux RAC par racMetierId.
A conserver
Le workflow dossier/timeline/statuts RAC peut etre garde et etendu.
  • Nouvelle entite: racMetier (nom, description, secteur, niveau, publication).
  • Nouvelle entite: racMetierRequiredDocument (label, obligatoire, formats, taille max, ordre).
  • Evolution: RacDossier avec racMetierId + documents soumis.
  • Validation serveur: refus 422 si pieces obligatoires manquantes/invalides.

Endpoints proposes

GET /api/rac/metiers/public GET /api/rac/metiers/{id} POST /api/rac/dossiers GET /api/rac/dossiers/{id} GET /api/rac/dossiers/{id}/timeline

Public: consultation metiers + depot dossier.

Admin endpoints proposes

POST /api/rac/metiers PATCH /api/rac/metiers/{id} DELETE /api/rac/metiers/{id} POST /api/rac/metiers/{id}/documents-requis PATCH /api/rac/metiers/{id}/documents-requis/{docId} DELETE /api/rac/metiers/{id}/documents-requis/{docId} GET /api/rac/dossiers?racMetierId=&statut=

Admin: gestion catalogue metiers + checklist docs + suivi candidatures.

Champs necessaires (creation metier RAC)

  • racMetier: nom, description, secteur, niveau, isPublished, isActive, ordreAffichage.
  • requiredDocuments[] (definis par admin): code, label, obligatoire, formatsAutorises[], tailleMaxMo, minFiles, maxFiles, ordre.
  • Le tableau requiredDocuments[] doit accepter un nombre variable d'elements.
  • Chaque metier peut avoir des documents differents (types, quantites, contraintes).
POST /api/rac/metiers { "nom": "Technicien froid et climatisation", "description": "Certification des acquis professionnels RAC", "secteur": "Froid & Climatisation", "niveau": "BT", "isPublished": true, "isActive": true, "ordreAffichage": 3, "requiredDocuments": [ { "code": "cv", "label": "CV detaille", "obligatoire": true, "formatsAutorises": ["pdf"], "tailleMaxMo": 5, "minFiles": 1, "maxFiles": 1, "ordre": 1 }, { "code": "attestation_travail", "label": "Attestations d'employeur", "obligatoire": true, "formatsAutorises": ["pdf", "jpg", "png"], "tailleMaxMo": 10, "minFiles": 1, "maxFiles": 5, "ordre": 2 }, { "code": "portfolio", "label": "Photos / preuves de realisations", "obligatoire": false, "formatsAutorises": ["pdf", "jpg", "png"], "tailleMaxMo": 20, "minFiles": 0, "maxFiles": 10, "ordre": 3 } ] }

Champs necessaires (candidature utilisateur)

  • Le dossier utilisateur doit pointer vers racMetierId (et non formationId).
  • Le frontend affiche dynamiquement les labels des documents requis du metier choisi.
  • Le backend doit refuser la soumission si un document obligatoire manque.
POST /api/rac/dossiers { "racMetierId": "uuid-metier", "candidat": "Nom Prenom", "email": "candidat@email.com", "telephone": "+2250700000000", "anneesExperience": 4, "competencesRevendiquees": ["Maintenance", "Diagnostic"], "documentsJoints": [ { "requiredDocumentCode": "cv", "url": "/uploads/rac/cv.pdf", "name": "CV", "type": "pdf" } ] } 422 si documents obligatoires manquants: { "message": "Documents obligatoires manquants", "missingDocuments": ["attestation_travail"] }

Plan de migration (court et sur)

  • Phase 1: ajouter metiers RAC + documents requis (sans casser l'existant).
  • Phase 2: accepter racMetierId sur POST dossier RAC + validation obligatoire.
  • Phase 3: deprecier progressivement la dependance formationId du module RAC.

Livrable attendu equipe backend

  • Creation metier RAC avec requiredDocuments[] dynamique dans une seule requete.
  • Endpoints operationnels + securisation admin/public.
  • Swagger mis a jour pour permettre l'integration frontend immediate.

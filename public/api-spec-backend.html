Contexte & Informations générales

Base de travail pour l'équipe backend

Objectif : Ce document recense les 4 nouvelles ressources API que l'équipe frontend requiert pour rendre dynamiques les sections de la page Entreprises du site CPU Formation. Les données sont actuellement statiques (hardcodées) dans le frontend.

Toutes les routes sont préfixées par : https://back.cpupme.com
Variable d'environnement frontend : NEXT_PUBLIC_API_URL
✅ Convention de réponse déjà adoptée
Le frontend s'attend au format uniforme suivant pour toutes les réponses : 
// Format de réponse standard (déjà utilisé sur /api/formation/formations/public)
{
  "success": true,
  "message": "...",
  "data": /* [] ou {} selon la ressource */
}

// En cas d'erreur
{
  "success": false,
  "message": "Description de l'erreur",
  "data": null

1. Packs Métiers Entreprises

Ressource : /api/entreprises/packs

Contexte frontend : La section "Packs Métiers" de la page /entreprises affiche actuellement 6 packs statiques codés en dur (Direction & Management, Commercial & Marketing, Finance, RH, Production, Digital & IT). Ces packs ont chacun une grille de prix B2B spécifique (par personne, groupe 8+, groupe 15+) et des informations de financement FDFP.

Pourquoi une API dédiée ? Ces données ne peuvent pas être dérivées de l'API formations existante car : les prix sont journaliers (pas annuels), la structure de groupe n'existe pas, et les taux FDFP sont des valeurs métier.
🔴 Priorité Haute B2B Public + Admin
Lecture publique
GET /api/entreprises/packs 🔓 Public

Retourne la liste complète de tous les packs métiers publiés, triés par ordre d'affichage.

📥 Query params optionnels
?categorie=finance — filtrer par catégorie métier
?actif=true — n'afficher que les packs actifs (défaut : true)

GET /api/entreprises/packs/:id 🔓 Public

Retourne le détail d'un pack par son id ou son slug. Utile pour une future page détail pack.

Administration (routes protégées — rôle admin)
POST /api/entreprises/packs 🔒 Admin

Crée un nouveau pack métier. Corps de la requête : même structure que la réponse GET (sans id, created_at, updated_at).

PUT /api/entreprises/packs/:id 🔒 Admin

Met à jour un pack existant (prix, formations, statut actif…).

DELETE /api/entreprises/packs/:id 🔒 Admin

Supprime ou archive un pack (préférer un soft-delete via actif: false).

2. Certifications & Labels de l'organisme

Ressource : /api/organisme/certifications

Ces certificats de conformité doivent pouvoir être mis à jour par l'équipe admin sans redéploiement frontend.

Besoin supplémentaire : Possibilité de joindre une copie scannée (PDF ou image) du certificat, affichable ou téléchargeable sur le site.

Administration (routes protégées — rôle admin)
POST /api/organisme/certifications 🔒 Admin

Crée une nouvelle certification. Corps : multipart/form-data pour permettre l'upload simultané du logo et du document PDF.

📎 Upload de fichiers
— logo : fichier image (PNG/JPG/SVG, max 2 MB)
— document : fichier PDF du certificat officiel (max 10 MB)
Le backend stocke les fichiers et retourne les URLs publiques dans logo_url et document_url.
PUT /api/organisme/certifications/:id 🔒 Admin

Met à jour une certification existante. Accepte multipart/form-data pour remplacer logo ou document, ou application/json pour les champs texte uniquement.

DELETE /api/organisme/certifications/:id 🔒 Admin

Supprime une certification et ses fichiers associés du stockage. Préférer un soft-delete via actif: false pour archiver sans supprimer.

4. Formulaires Entreprises (Leads commerciaux)

Ressource : /api/entreprises/leads

Contexte frontend : La page /entreprises dispose d'un formulaire de contact en modal. Lorsqu'un utilisateur clique sur "Postuler" depuis un pack métier, le formulaire est pré-rempli (typebesoin = pack-metier et packInteresse).

Besoin backend : Persister chaque demande, permettre un suivi commercial (nouveau, en-cours, traité, clos), et offrir une interface d'exploitation côté admin (filtre, tri, changement de statut, historique).
🔴 Priorité Haute Lead B2B Public + Admin RGPD
Soumission publique
POST /api/entreprises/leads 🔓 Public

Enregistre une nouvelle demande entreprise depuis le formulaire modal (devis, pack métier, accompagnement, audit, etc.).

📌 Règles de validation minimales
entreprise, secteur, nom, fonction, email, tel, typebesoin, collaborateurs, delai, rgpd sont requis.
Si typebesoin = pack-metier, alors packInteresse devient requis.
Le backend doit refuser toute soumission avec rgpd = false (HTTP 422).
Exemple de payload (request body)
{
  "entreprise": "Banque Atlantique CI",
  "secteur": "Banque",
  "nom": "Kouame Jacques",
  "fonction": "DRH",
  "email": "drh@banque-atlantique.ci",
  "tel": "+2250700000000",
  "typebesoin": "pack-metier",
  "packInteresse": "Pack Direction & Management",
  "collaborateurs": "11-30",
  "delai": "court",
  "message": "Nous souhaitons démarrer en mai.",
  "rgpd": true
}
Exemple de réponse
{
  "success": true,
  "message": "Demande enregistrée avec succès",
  "data": {
    "id": "lead_01J8FKW7P7Q3M7K4H6R1M2P9AA",
    "statut": "nouveau",
    "source": "page-entreprises-modal",
    "created_at": "2026-04-03T11:20:00.000Z"
  }
}
Back-office commercial (routes protégées — rôle admin)
GET /api/entreprises/leads 🔒 Admin

Liste paginée des demandes pour le tableau de suivi commercial.

📥 Query params recommandés
?page=1&limit=20 — pagination
?statut=nouveau — filtre statut
?typebesoin=pack-metier — filtre type
?q=banque — recherche texte (entreprise, nom, email)
GET /api/entreprises/leads/:id 🔒 Admin

Retourne le détail complet d'une demande (incluant historique statut et métadonnées techniques).

PATCH /api/entreprises/leads/:id/status 🔒 Admin

Met à jour le statut commercial de la demande (pipeline de traitement).

Payload status
{
  "statut": "en-cours",
  "noteInterne": "Premier échange planifié avec le DRH"
}
⚠️ Workflow de statut recommandé
nouveau → en-cours → traite → clos
Conserver l'historique des changements (qui, quand, ancien/nouveau statut).

⚠️ Points d'attention pour l'implémentation
  • Soft-delete : Préférer actif: false plutôt qu'une suppression définitive pour les packs et certifications.
  • Stockage fichiers : Les uploads (logos PNG, PDFs) doivent être hébergés et accessibles via une URL publique stable (ex: S3, Cloudinary ou stockage local nginx).
  • CORS : Les URLs de fichiers doivent être accessibles depuis https://cpupme.com et http://localhost:3000 en développement.
  • Format devise : Tous les montants sont en XOF (Franc CFA), entiers, sans décimales.
  • Tri par défaut : Toutes les listes sont retournées triées par ordre ASC puis created_at ASC.
  • RGPD : Ne jamais persister un lead avec rgpd = false. Prévoir journalisation du consentement (timestamp + ip éventuelle selon conformité locale).
  • Anti-spam : Ajouter une protection basique (rate limit IP/email) sur POST /api/entreprises/leads.
